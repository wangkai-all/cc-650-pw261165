# 客服来信类别占比分析工具

不重新训练分类器，仅用一个**带真值的独立校验集**估计新批次（只有预测标签）的真实类别占比，
并对「类内误判行为是否稳定」这一核心假设给出诚实的诊断。

## 它解决什么问题

分类器会把真实类别 `k` 误判成预测类别 `j`。直接数新批次的预测标签得到的是**被污染的分布**，
不是真实占比。本工具用校验集估计列条件转移矩阵 `X`（`X[j,k] = P(预测=j | 真实=k)`，每列和为 1），
在模型 `q ≈ X·p` 下反推真实占比 `p`：

- `q`：新批次预测标签的观测分布
- `p`：新批次真实类别占比（待估计）

## 核心方法与硬约束

反推**不做矩阵求逆**，而是在单纯形上解约束二次规划（`app/core/solver.py`）：

```
minimize  0.5 · ‖X·p − q‖²
subject to p ≥ 0,  Σp = 1
```

- 主路径 SLSQP；失败时回退到 FISTA 投影梯度（Duchi 单纯形投影）。
- 结果天然非负、总和为 1——**不是先求逆再强行截断负值**。
  `tests/test_core.py::test_no_inversion_in_estimate_path` 用 AST 扫描求解路径，
  禁止出现 `inv / pinv / solve / lstsq / normal` 等调用。
- 响应里 `estimate.constraints_ok` 与 `estimate.inverse_used` 两个布尔标志可直接核验。

### 可识别性（什么时候反推不出来）

`app/core/identifiability.py` 诊断两类结构性不可识别：

1. **零列**：某真实类别在校验集中完全没有样本，其占比无法从数据识别，仅受单纯形约束牵制。
2. **近似重复列**：两个真实类别的条件分布余弦相似度过高（默认 ≥ 0.98），组内占比分不清，
   只能可靠识别组总和。并查集给出不可区分分组，附 SVD 有效秩与条件数。

页面会明确点名**哪些比例无法分清**。可勾选类别创建**合并视图**重算
（`app/core/merge.py`），合并只是派生视图，原始类别定义始终保留、可随时回退。

### 稳定区间（bootstrap）

对校验集逐行重抽重建 `X*` 并重解 QP，得到每个占比的 90% / 95% 区间（`app/core/bootstrap.py`）。
结构性缺席列在重抽中保留零列（求解器本就支持），仅当活动列偶然重抽丢光才跳过该次重抽。

### 正向推回残差

用 `X·p̂` 把估计正向投影回预测分布，与新批次观测 `q` 对比，给出 RMSE 与总变差（TV）距离。

## 最重要的统计警示：饱和模型没有边际检验功效

当 `X` 是方阵且满秩、`p` 为自由参数时，QP 能令 `X·p̂ ≡ q` **恒成立（自由度 0，饱和拟合）**。
此时任何只看边际预测分布的拟合优度检验观测统计量恒为 0，**对类内漂移零功效**。
本工具不会假装检出了什么：

- 边际检验响应里 `saturated_no_power=true`，并附解释文案。
- 真正能识别类内漂移的是**转移矩阵两样本检验**（逐列 TV + 参数自助零分布），
  但它要求新批次也有真值标签——真实业务里需定期抽小样本人工复核。
- 页面明确写出：**「看不出异常」≠ 类内稳定假设已被证明。**

## 两组内置虚构流量（`app/core/synthetic.py`）

| 场景 | 改变了什么 | 预期诊断 |
|------|-----------|----------|
| A | **只改类别占比**，类内误判机制不变 | 边际残差为 0；转移检验 `misfit_flagged=false` |
| B | 占比 **和** 类内误判方式同时改变 | 转移检验 `misfit_flagged=true`，漂移列被点名 |

诊断页一键跑 A/B，可对照验证工具确实能抓住 B 的明显失配，同时不会在 A 上误报。

## 运行

需要 Python 3.10+，唯一第三方依赖是 numpy。

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 推荐：隔离模式启动包装脚本（自动注入项目路径，解释器以 -I 运行）
./scripts/run.sh serve --host 127.0.0.1 --port 8000 --data-dir ./data

# 或直接用 CLI（非 -I 时模块路径正常）
.venv/bin/python -m app.cli serve --port 8000
.venv/bin/python -m app.cli seed     # 预生成一份内置虚构演示数据
```

打开 http://127.0.0.1:8000/ ，三个页签：

- **校验集管理**：上传校验集（CSV/JSON，需 `y_true`/`y_pred`，支持中文列名 真值/预测类别 等）、
  查看混淆矩阵热力图与逐类混淆明细、可识别性诊断、类别合并。
- **占比反推分析**：粘贴新批次预测标签，对照朴素计数 vs 反推占比、bootstrap 区间、正向残差。
- **拟合诊断**：A/B 虚构场景的饱和检验与转移矩阵漂移检验。

## 安全约束（不可信上传）

- Web 服务纯标准库 `http.server`，写接口只接受 JSON 文本，不解析 multipart、不执行任何上传内容。
- 每个数据集落在 `data_dir` 下独立子目录，原始上传字节与解析后的行分开存储。
- 静态文件服务带路径穿越防护，`..` 越界请求返回 404。
- 处理外部下载/解压数据时：每个来源放进**独立空目录**、脚本放另一目录、路径以参数传入，
  并用 `python -I` 运行，使解释器不把脚本目录/CWD 放进 `sys.path`，避免植入的 `json.py`
  之类在 import 时被执行。

## 目录结构

```
app/core/    混淆矩阵、单纯形求解、可识别性、合并、bootstrap、合成数据、导入、SQLite 存储、管线
app/web/     标准库 HTTP 服务 + 原生 JS/内联 SVG 前端（无框架、无构建步骤）
scripts/     -I 隔离模式启动包装
tests/       Python 单测 + Node DOM 冒烟 + 真实响应 fixture
```
